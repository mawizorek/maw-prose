# Legacy script review

Source: `ProductionCalendarFormat` script export, read 2026-08-08.

## ✅ PORT the bones

| Script | Why |
|---|---|
| `CREATE PRODUCTION WORKDAYS` | The generator. Two loops: production days forward from first rehearsal, pre-pro backward. Then sort by DATE → stamp sequential SORT → re-sort by SORT. This is the WEEKS → WORKDAYS pattern. ⚠️ Kill the magic `$daysNeeded + 10` on the pre-pro exit. |
| `showRelevantDates` + `showNecessaryRecords` | Find `HideDateFromCalendar = 1` → **Show Omitted Only** → constrain to `DATE > Calendar_START - 1`. The found-set trick that makes hide-as-existence work. Proof the stamped-hide call was right. |
| `EXPORT Calendar Set` | Filename builder (`YYMMDD`, long/short title prompt) + four-output run (8.5x11 landscape, 8.5x11 portrait, 11x17 expanded, agenda). **The whole script becomes PRINT_PRESETS rows.** |
| `Workday Sort INPUT` | Sequential SORT stamp after a date sort. Keeps print order independent of date. |
| `PRINT_SETUP` pair | Parameter `1` = landscape, else portrait. Clean. Becomes `OutputSize` + orientation on the preset. |

## 🔄 TRANSFORM

| Script | Problem | New home |
|---|---|---|
| `REMOVE ShortName` | Strips `[BL] ` by looping and mutating `Event Name` in place | Raw stays in `Raw_Payload`; cleaned name is a separate field. Never mutate. |
| `remove notes` | Strips `<...>` the same way | Same |
| `CREATE_multipleDays` | A multi-day event is DUPLICATED into one record per day, flagged `autoGenerated=1` | 🔴 **Needs a decision** — EVENTS grain is currently one row per event. Either keep a span as one row and render across days, or adopt duplicate-per-day explicitly. |
| `Events Agenda View SORT` | Hides a business rule in a sort: finds `Event Name == "Rehearsal"` then Show Omitted Only, so **the agenda deliberately excludes plain rehearsals** | That is a preset FILTER, not a sort → PRINT_PRESETS |
| 6x `stored production INFO` | Each hardcodes title / short / first-rehearsal / last-needed / director / semester / course + all six range fields into the ONE SETUP record, then regenerates | ⭐ **These scripts ARE the PRODUCTIONS table, written as code.** All six delete outright once records exist. |

## 🪦 KILL

- **`import Records`** — Show All → **Delete All Records** → Import. **`REPLACE THE SET`** deletes *again* before calling it. Double delete, and the reason history is impossible → UPSERT on `TaskID` + `fkProduction`.
- **`Delete ClickUp Rows`** — finds `Event Name = "Task Name"` and deletes it. That is the CSV **header row** landing as a record. Pure CSV artifact; an API pull has no headers.
- **`AUTO_WorkdayID`** — assigns dates via `NumberOfRecordsPerPortal` / `NumberAvailablePreProRecords` math. Portal geometry driving data placement.
- **`updatePreproCounter`** / **`updateUnscheduledCounter`** — counters existing only to feed that geometry.
- **`checkHIGHlight`** / **`checkLOWlight`** → CALENDAR_EMPHASIS relationship. `checkHideWorkday` survives.
- **`refreshFilePath`** — deletes and recreates the SETUP_EXPORT record to refresh a path. `Get ( FilePath )` replaces it.
- **`removeTextFormatting`** — strips styling off a field that should never have held styling.
- **`ColorMONTHStyle`** / **`ColorSTATUSStyle`** / **`updateEventSTYLE`** / **`updateWORKDAYcolor`** / **`TextColorHex`** / **`color_Text`** — six scripts writing RGB into stored text. STYLES resolves colour at render.
- **FCCalendar addon** (~25 scripts) — third-party widget. `FCCalendar Import Sample Data` calls `https://fakermaker.geist.ws/api/generate` from inside a production file.

## 🔴 Live bugs found

1. **`RGB ( $R ; $G ; $R )`** in BOTH `ColorSTATUSStyle` and `updateWORKDAYcolor`. **Blue takes red's value.** Every status and month colour in that file is wrong and nobody noticed — the argument for one resolution path.
2. **Three flag scripts, no priority.** `checkHideWorkday` / `checkHIGHlight` / `checkLOWlight` each set their own flag to `1` with no resolution between them. A day in two ranges gets two flags and the layout picks. **The overlap bug was always there**, it just never fired on single-range use.
3. **`updateWORKDAYcolor` ships a live `Show Custom Dialog`** debug popup, uncommented.
4. **`One Acts INFO`** has `Course Numbers: "THTR TIME course"` — copy-pasted from TIME.
5. **`import Records`** references two `<Missing Field>` entries in its import mapping.
