# PRODUCER_INFO

⬜ **A name in the index with no table behind it yet.**

[[PRODUCERS](@table-producers)] already holds the producing organization: name, short name, display name, and the wide/square logos that make the app portable across companies.

**So the open question is whether PRODUCER_INFO is anything at all.** Two readings:

- **A fold-in.** It is the same entity and the name is a leftover → delete it from the index and point at PRODUCERS.
- **A child.** It is per-production producer DETAIL (billing contact, credit block wording, a logo override for one show) → then it is a join between PRODUCTIONS and PRODUCERS, not a second producer table.

🚦 **Unruled. Do not build it on either reading** — the second one is a join wearing an entity's name, which is exactly how a schema grows a duplicate.

This page exists so the index link resolves. `unlisted`: reachable, not in the nav.
