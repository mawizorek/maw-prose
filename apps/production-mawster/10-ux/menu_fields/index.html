    Fields¶

    Fields, per table. Pick a table to open its field menu.

    ← Database

    ⭐ There is no flat field census, on purpose. A field only means anything next to its table's grain, so this menu routes per table — the answer ruled 2026-09-30. Each row opens that table's page, where the field menu renders from the data: catalog: block. The source of every one of those tables is 20-tables/<TABLE>.tsv, columns Field_Name | Type | Notes, and that TSV is the only place a field is ever written down.

    🚫 Never retype a field onto this page. The moment a field name lives in two files, one of them is wrong and nobody knows which.

    Normalized¶

    • Producers

      Who presents the work. Carries the logo.

    • Roles

      Roles in production.

    • Productions

      One production. Two dates, ever — everything else about a show is a join.

    • PRODUCTION_CALENDARS

      Joining entity to output.

    • Weeks

      One printed week row. Parent is the CALENDAR, not the production.

    • Workdays

      One canonical row per real date. Calendar-agnostic.

    • STANDARD_EVENTS

      Canonical cross-season event types. The reporting spine and the skin layer.

    • Location Types

      Venue, rehearsal room, shop, storage, off-campus.

    • ORGANIZATIONS

      Orgs. Main app skin and default. Rarely touched.

    Working data¶

    • Events

      The current, printable event set. One row per event.

    • EVENTS_workday

      One row per event per day. A projection, rebuilt at import, never edited.

    • CALENDAR_EMPHASIS

      N typed callouts per calendar. Replaces the fixed highlight/lowlight pairs.

    • Assignments

      Someone-or-nobody doing a role on a show.

    • EDITIONS

      One export. Where editions live.

    • Versions

      The current, printable event set. One row per event.

    • Locations

      Places. Venues, rooms, shops, off-campus.

    Styling¶

    • Styles

      One colour table, one resolution path.

    • Themes

      One colour table, one resolution path.

    • THEMES_x_STYLES

      The set of STYLE objects per THEME.

    • Colors

      Color (pallete refernces).

    • Typography

      Typography tokens for the theme. Source THEME_TYPOGRAPHY.tsv.

    Import¶

    • import_SESSIONS

      One pull from ClickUp.

    • IMPORT_SOURCES

      To hold CLikcup Paths, and Dorpbox paths, and CSV files actually too.

    • import_EVENTS

      Raw ClickUp pulls, append-only.

    Export¶

    • PRINT_SESSIONS

      One export. Where editions live.

    • EXPORT_PRESETS

      Saved export settings. The HOW, reusable forever.

    • PRINT_SETS

      A batch of documents to produce together. The print hub.

    • PRINT_SET_ITEMS

      One output in a print set. Where overrides live.

    Globals and utility¶

    • GLOBAL_USE

      Session state only. The hub lens.

    • GLOBAL_EXPORT_VARIABLES

      Session state only. The hub lens.

    • Utility Reports

      Utility REPORTS.

    • Utility logs

      One row per run. Nothing in the file is allowed to happen unrecorded.

    • Utility Logs

      Utility Logssss.

    Two tables have NO field menu, and that is correct

    FISCAL_YEARS and PEOPLE have a page but no .tsv twin. Both are external data sources — other FileMaker files own their fields (URITP_GLOBAL and URITP_PEOPLE). ⭐ Writing a field list for them here would be transcription of somebody else's schema, which goes stale without anyone touching this repo. They are deliberately absent from this menu and present on [Tables].

    ⚠️ PEOPLE is its own app, ruled 2026-08-07: a table with two owners has no owner. Its field truth lives in the uritp-people build, and the ClickUp → FileMaker pull is what keeps it current.

    The audit five

    Every normalized table's TSV ends with the same block — PrimaryKey, CreationTimestamp, CreatedBy, ModificationTimestamp, ModifiedBy. ⚠️ The marker text reads [Audit Feilds], misspelled, across the TSVs. Cosmetic, consistent, and fixable in one sweep whenever somebody is in there anyway. 🚫 Not swept yet — it touches roughly 35 files for a cosmetic gain, which is a decision, not a chore.
